# Sonic Animation Viewer PRD

## 1. 문서 정보

- 제품명: 소닉 애니메이션 뷰어
- 대상 폴더: `Labs/LEC09`
- 주 실행 파일: `sonic_animation_viewer.py`
- 그래픽 라이브러리: Python `pico2d`
- 스프라이트 이미지: `sonic-sprite.png`
- 상태: 개발 요구사항

## 2. 제품 개요

소닉 스프라이트 시트에 포함된 모든 동작을 화면에서 차례대로 재생하는 데스크톱 애플리케이션이다. 각 동작을 5회 반복한 뒤 1초간 쉬고 다음 동작으로 넘어가며, 마지막 동작까지 재생하면 처음부터 다시 무한 반복한다. 스프라이트가 화면에서 충분히 크게 보이도록 표시한다.

## 3. 목표와 성공 기준

### 목표

1. 스프라이트 시트의 모든 동작을 식별하고 애니메이션으로 재생한다.
2. 동작별 반복 횟수와 동작 사이 대기 시간을 일관되게 적용한다.
3. 확대된 이미지에서도 화면 안에 캐릭터가 잘 보이도록 한다.
4. 소스 코드를 단일 Python 파일로 유지하고, 작은 개발 단계와 커밋으로 구현한다.

### 성공 기준

- 프로그램 실행 시 `Labs/LEC09/sonic-sprite.png`를 로드해 애니메이션을 표시한다.
- 시트에 포함된 모든 동작이 정의된 순서로 누락 없이 재생된다.
- 각 동작은 정확히 5회 재생되고, 다음 동작 시작 전 1초간 대기한다.
- 마지막 동작 뒤에도 순환 대기 시간을 거쳐 첫 동작으로 돌아가며 재생이 계속된다.
- 캐릭터가 원본보다 크게 표시되고, 잘림 없이 창 안에서 식별 가능하다.
- 실행 코드가 `sonic_animation_viewer.py` 한 파일에만 들어간다. 스프라이트 이미지 파일은 별도 에셋으로 유지한다.

## 4. 대상 사용자와 사용 시나리오

### 대상 사용자

- 2D 게임 프로그래밍 실습에서 스프라이트 애니메이션을 확인하려는 개발자 또는 학습자

### 대표 사용 시나리오

1. 사용자가 `Labs/LEC09`에서 `sonic_animation_viewer.py`를 실행한다.
2. 프로그램은 같은 폴더의 `sonic-sprite.png`를 읽는다.
3. 첫 번째 동작부터 순서대로 캐릭터 애니메이션을 표시한다.
4. 사용자는 각 동작의 5회 재생과 1초 간격을 포함한 전체 순환을 확인한다.

## 5. 범위

### 포함

- `pico2d`를 사용한 창 생성, 이미지 로딩, 그리기 및 종료 처리
- 스프라이트 시트에서 동작별 프레임 영역을 지정하고 애니메이션 재생
- 동작별 5회 반복
- 동작 간 1초 대기
- 전체 동작을 순환하는 무한 재생
- 화면 크기에 적절한 확대 표시
- 단계별 구현 및 단계별 커밋이 가능한 개발 계획

### 제외

- 동작 선택, 재생/일시정지 버튼, 설정 메뉴 등 사용자 인터페이스
- 스프라이트 시트 편집 또는 자동 리깅 도구
- 사운드, 배경, 점수, 게임플레이 기능
- 단일 실행 파일을 만들기 위한 패키징
- 여러 이미지 에셋이나 추가 실행용 Python 모듈의 도입

## 6. 기능 요구사항

### FR-1. 에셋 로딩

- 애플리케이션은 `Labs/LEC09/sonic-sprite.png`를 사용한다.
- 소스 파일 위치와 실행 작업 디렉터리가 달라도 에셋 경로를 안정적으로 찾도록 한다.
- 이미지 로딩 실패 시 원인을 확인할 수 있도록 오류를 명시적으로 알리고 프로그램을 정상 종료한다.

### FR-2. 애니메이션 정의

- 스프라이트 시트에 실제로 포함된 모든 동작을 재생 대상으로 등록한다.
- 동작별 프레임 범위, 프레임 수 및 프레임 재생 속도를 명확하게 정의한다.
- 동작 순서는 스프라이트 시트의 구성과 실습 목적에 맞게 고정하며, 누락 없이 한 번씩 등록한다.
- 시트의 실제 프레임 배치와 각 동작의 경계는 구현 단계에서 에셋을 확인해 확정한다. 근거 없이 동작 수나 프레임 좌표를 가정하지 않는다.

### FR-3. 프레임 재생

- 현재 동작의 프레임을 시간에 따라 갱신하여 연속된 애니메이션처럼 표시한다.
- 현재 동작이 한 번 끝나면 해당 동작의 첫 프레임으로 돌아가 총 5회 재생한다.
- 동작별 재생 속도는 읽기 쉽고 수정하기 쉬운 방식으로 정의한다.

### FR-4. 동작 전환과 반복

- 한 동작의 5회 재생이 완료되면 1초간 대기한다.
- 대기 후 다음 동작으로 전환한다.
- 마지막 동작이 끝나면 동일한 대기 시간을 둔 후 첫 번째 동작으로 돌아간다.
- 마지막 동작 다음에도 쉬는 동작이 포함되는 해석으로 순환 규칙을 일관되게 적용한다.
- 별도의 종료 입력이 없으면 전체 시퀀스를 계속 반복한다.

### FR-5. 표시와 확대

- 캐릭터가 원본 이미지보다 크게 보이도록 확대해 그린다.
- 확대된 캐릭터는 창 경계 안에 들어오고, 불필요하게 잘리거나 왜곡되지 않아야 한다.
- 프레임마다 캐릭터의 화면상 위치가 불필요하게 흔들리지 않도록 기준 위치를 유지한다.

### FR-6. 프로그램 수명 주기

- 창을 열어 애니메이션을 실행하고, 프레임 갱신 중 사용자 종료 요청을 처리한다.
- 종료 시 이미지와 그래픽 리소스를 정리하고 라이브러리 종료 절차를 호출한다.

## 7. 비기능 요구사항 및 제약

- 구현 언어는 Python이며 그래픽 및 이미지 표시에는 `pico2d`를 사용한다.
- 실행 로직은 `sonic_animation_viewer.py` 단일 파일에 작성한다.
- 에셋은 `Labs/LEC09/sonic-sprite.png`를 사용하며 Python 실행 파일과 분리한다.
- 프레임 갱신과 대기 처리는 프레임 속도에 의존하는 바쁜 대기 대신 시간 기반으로 구현한다.
- 코드와 상수는 동작별 프레임 정의, 반복 횟수, 간격 및 확대율을 쉽게 점검할 수 있도록 구성한다.
- 각 개발 단계를 검증 가능한 크기로 나누고, 완료된 단계마다 별도의 커밋을 만든다.

## 8. 완료 조건 및 검증

제품은 다음 항목을 모두 만족할 때 완료된 것으로 본다.

1. `Labs/LEC09`에서 실행했을 때 스프라이트 이미지가 오류 없이 표시된다.
2. 실행 작업 디렉터리를 프로젝트 루트로 바꿔 실행해도 에셋을 정상적으로 찾는다.
3. 확인된 모든 동작을 정의된 순서로 재생한다.
4. 타이밍을 관찰하거나 임시 계측으로 확인했을 때 각 동작이 5회 반복되고 동작 전환 간격이 1초다.
5. 전체 동작을 마친 뒤 처음 동작으로 돌아가 재생을 계속한다.
6. 창을 닫는 요청에 정상적으로 반응하고 실행이 종료된다.
7. 실행 코드는 `sonic_animation_viewer.py` 하나에만 존재한다.
8. 각 구현 단계의 변경과 검증이 개별 커밋으로 기록된다.

## 9. 단계별 개발 계획

아래 단계는 작고 검증 가능한 변경을 쌓아 PRD의 요구사항을 완성하는 순서다. 각 단계를 완료하고 확인한 뒤 별도 커밋으로 기록한다. 실제 프레임 개수와 좌표는 스프라이트 시트를 확인한 후 확정한다.

1. **작업 공간 확인** — LEC09의 파일과 에셋 경로를 확인하고 작업 기준을 정한다.
2. **스프라이트 시트 조사** — 이미지 크기, 프레임 배치 및 동작별 경계를 파악한다.
3. **동작 목록 작성** — 시트에서 확인한 모든 동작과 재생 순서를 기록한다.
4. **프레임 정의 설계** — 동작별 프레임 좌표와 프레임 수를 정리한다.
5. **재생 타이밍 설계** — 프레임 속도, 5회 반복, 1초 대기 규칙을 정리한다.
6. **Python 실행 환경 확인** — Python 및 `pico2d` 실행 가능 여부를 검증한다.
7. **단일 파일 골격 작성** — `sonic_animation_viewer.py`의 초기 구조를 만든다.
8. **라이브러리 초기화 구현** — `pico2d` 초기화, 창 생성 및 종료 흐름을 추가한다.
9. **에셋 경로 결정 구현** — 실행 위치와 무관하게 같은 폴더의 스프라이트를 찾는다.
10. **이미지 로딩 구현** — 스프라이트를 로드하고 로딩 오류를 드러낸다.
11. **기본 화면 출력 구현** — 이미지의 일부를 정지 화면으로 창에 출력한다.
12. **확대 및 배치 구현** — 캐릭터를 충분히 크게 표시하고 창 안에 배치한다.
13. **프레임 선택 구현** — 정의한 좌표를 사용해 원하는 프레임을 표시한다.
14. **첫 동작 애니메이션 구현** — 첫 동작의 프레임을 시간 기반으로 순환한다.
15. **동작별 프레임 데이터 확장** — 조사한 모든 동작의 프레임 정의를 추가한다.
16. **동작 재생 상태 구현** — 현재 동작과 프레임을 명확한 상태로 관리한다.
17. **동작 1회 완료 판정 구현** — 프레임 순환 완료를 감지해 반복 횟수를 계산한다.
18. **동작별 5회 반복 구현** — 5회 재생이 끝난 후 다음 전환 단계로 진행한다.
19. **1초 대기 상태 구현** — 동작 종료 후 시간을 기준으로 1초 대기한다.
20. **다음 동작 전환 구현** — 대기 종료 후 다음 등록 동작으로 이동한다.
21. **마지막 동작 순환 구현** — 마지막 동작 후 대기하고 첫 동작으로 돌아간다.
22. **전체 무한 반복 검증** — 복수 사이클에서 동작 순서와 반복 횟수를 확인한다.
23. **종료 및 리소스 정리 검증** — 창 종료 요청과 라이브러리 종료를 확인한다.
24. **실행 경로 검증** — LEC09 폴더와 프로젝트 루트에서 각각 실행해 에셋 로딩을 확인한다.
25. **최종 요구사항 점검** — 단일 파일 제약, 확대 표시, 타이밍, 전체 동작 포함 여부를 확인하고 완료 커밋을 만든다.

## 10. 구현 시 확정한 값

- 프레임 표시 간격은 0.08초(초당 12.5프레임)로 설정했다.
- 창 크기는 960×720이고 캐릭터 프레임은 8배 확대해 화면 중앙에 표시한다.
- 이미지의 실제 크기와 전체 동작 프레임 범위는 다음 조사 결과 및 구현 데이터로 확정했다.

### 스프라이트 시트 조사 결과

- `sonic-sprite.png`는 399×525 RGBA 이미지이며, LEC08 애니메이션 예제의 스프라이트와 동일한 파일이다.
- 기존 예제에서 사용한 여섯 동작 외에도 시트 아래쪽에 소닉 프레임 묶음이 더 있어 모두 애니메이션 데이터에 포함한다.
- 구현 시 사용할 동작 순서와 프레임 수는 `normal`(11), `run`(12), `jump`(6), `attack`(6), `roll`(9), `rolling`(6), `spin_attack`(6), `turnaround`(6), `impact`(2), `run_alt`(8), `reaction`(4)이다. 총 11개 동작, 76프레임이다.
- 동작 이름은 기존 예제의 명칭을 유지하고, 나머지는 프레임의 시각적 묶음을 구분하기 위한 구현 이름이다.
- 제목, 크레딧, 테일즈 등 소닉 애니메이션이 아닌 시트 요소는 재생 대상에서 제외한다.

## 11. 구현 검증 기록

- 전체 순환 시뮬레이션: 11개 동작의 등록 순서를 두 차례 확인했다. 각 동작은 5회 프레임 순환 후 1.000초 대기하고 다음 동작으로 넘어갔으며, `reaction` 이후 `normal`로 돌아왔다.
- 종료 및 리소스 정리: 창 닫기, ESC 입력, 이미지 로딩 실패 경로에서 종료 동작과 `close_canvas()` 호출을 확인했다.
- 실행 경로: 프로젝트 루트와 `Labs/LEC09`를 현재 작업 디렉터리로 각각 사용해도 같은 스프라이트 파일을 찾는 것을 확인했다.
- 좌표 및 정적 검사: 76개 프레임 사각형이 모두 399×525 이미지 내부에 있고, Python 문법 검사 및 Pylance 파일 진단에서 오류가 없음을 확인했다.
- `pico2d` 실환경 스모크 테스트: 960×720 창 생성, 이미지 로드, 8배 확대 프레임 그리기 및 창 종료를 확인했다.
